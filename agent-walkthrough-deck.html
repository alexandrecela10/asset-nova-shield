System design

A deterministic DAG, not an autonomous loop

Shield is a directed acyclic graph (DAG) pipeline where each node has a defined input, output, and quality gate. The LLM is used where language understanding is the problem. Code is used where being wrong is unrecoverable. Humans approve every external action.

LLM Judgment tasks

Threat detection, clause interpretation, evidence linking, response drafting. The LLM reads and reasons across thousands of documents where pattern matching across unstructured text is the core challenge.

Code Deterministic tasks

Document parsing, deadline computation, citation verification. These use rules engines and date math. An LLM never computes a date or fabricates a document reference. Every output is auditable and reproducible.

Human Decision tasks

Defense strategy, response approval, claim valuation. The agent surfaces evidence and drafts, but the human owns the decision. Nothing leaves the system without a named approver's sign-off.

Why a DAG, not an agent loop? Predictable execution order. Each node's output is testable independently. If detection improves, evidence and drafting don't regress. The governance kernel wraps every node: scope check, action allowlist, audit log.

Quality gates

How we know it works — evals at every layer

Every node in the pipeline has a testable quality gate. The eval suite runs on a golden set of confirmed events. No update ships unless it passes all gates on the expanded golden set.

LLM Threat detection precision

Target: 85%

False alarms destroy trust. Precision is the primary metric, not recall. Better to miss a low-value event than to flood the team with noise.

Method: expert-labeled events on closed projects. Backtest before live.

Example test: feed the agent 50 site reports from a closed project. An expert already labeled 8 real threats and 42 non-events. Does the agent flag the 8 threats without flagging more than 1-2 false alarms?

Code Citation accuracy

Target: 99.5%

Every citation in a draft must resolve to an actual document, section, and page. Deterministic verifier checks after LLM generates.

Method: automated resolver. Every cite is a lookup, not a generation.

Example test: agent drafts a response citing "Clause 4.12, p.88". The verifier opens the contract file, goes to p.88, and confirms Clause 4.12 exists there. If the page or clause is wrong, the citation fails.

Code Deadline accuracy

Target: 100%

Date math is code, never LLM. An error here means a missed deadline and lost rights. Zero tolerance.

Method: unit tests on anchor extraction + date arithmetic.

Example test: event date = 4 Aug, contract says "21 days", Amendment 2 overrides to "14 days for Areas 6-8". Expected deadline: 18 Aug. Does the code pick up the amendment and compute 18 Aug, not 25 Aug?

LLM Hallucination in drafts

Target: 0 in approved outputs

Every sentence in a draft must trace back to a source document. Citation verifier catches fabricated references. Human review catches fabricated reasoning.

Method: citation resolver + human gate. Double barrier.

Example test: agent writes "as stated in letter C-1205 dated 15 Aug". Verifier checks: does C-1205 exist? Is it dated 15 Aug? If the letter doesn't exist or the date is wrong, the draft is blocked before anyone sees it.

LLM Defense position accuracy

Target: 80% agreement with expert

Shield's "owner advantage" vs "supports contractor" tagging on each document must match what an expert claims consultant would say.

Method: expert review on closed-project backtests. Calibrate before live.

Example test: give the agent 6 documents from a resolved dispute. An expert tagged 3 as "owner advantage" and 3 as "supports contractor". Does the agent agree on at least 5 of 6? Where it disagrees, is the reasoning defensible?

Human Draft approval rate

Target: 70% approved with minor/no edits

If the team rewrites most drafts, the agent isn't learning their style. Edit diffs feed the self-improving loop. Approval rate should trend up over time.

Method: tracked via disposition log. Weekly calibration.

Example test: after 4 weeks, count: of the last 20 drafts, how many did Rania approve as-is or with small wording changes? If less than 14 of 20 (70%), the drafting model needs retuning on her team's style.

Kill criteria: if detection precision stays below 60% after 8 weeks of tuning, or the team stops reviewing for 4 consecutive weeks, pause deployment and return to backtest mode. These thresholds are initial hypotheses — they will be calibrated through Phase 0 backtesting on real project data.

Thresholds, templates, golden set

Dismissals reduce noise

When the team dismisses a false alarm, Shield raises its threshold for that pattern. Fewer irrelevant flags over time.

Edits sharpen drafts

When the team rewrites a response before sending, the edit diff is captured. Draft quality improves to match how the team actually writes.

Approvals confirm what matters

Confirmed events grow the golden eval set. No update ships unless it passes on all confirmed events. The test suite gets harder over time.

Full sovereignty: all retraining happens inside the customer's environment (in-region VPC or on-prem). Dispositions never leave. Your project data never improves someone else's agent. No shared model, no data export, no cross-tenant learning. Guaranteed via NovaOS.
